# VZ bot 2.0 — мультипользовательский режим

## Что изменилось

Раньше всё лежало в одном `config.json`: одна сессия, один список чатов, один список каналов.
`/activate` давал доступ **к этим же данным**, поэтому новый пользователь видел чужой аккаунт.

Теперь:

- `config.json` — только общие настройки приложения: `apiId`, `apiHash`, `botToken`, `ownerId`, ключи регистрации.
- `users.json` — личная карточка каждого пользователя: своя сессия Telegram, свои вз-чаты, свои каналы для тапов, свой автопост, свой канал договоров, своя история тапов.
- У каждого пользователя поднимается **отдельный клиент Telegram** со своим обработчиком сообщений. Пересечений между пользователями нет.

## Путь нового пользователя

```
/activate ABCD-1234      → создаётся ПУСТАЯ карточка
/login +79990000000      → код приходит на ЕГО номер
/code 12345
/password ...            → если включена 2FA
/add_chat <ссылки>       → его собственные вз-чаты
/add_channel <ссылки>    → его собственные каналы для тапов
/deals_channel <ссылка>  → его канал с договорами
```

## Канал договоров о ВЗ

- `/deals_channel <ссылка|@юз|id>` — выбрать канал
- `/deals_channel` — показать текущий
- `/deals_channel off` — отключить
- `/create_deals_channel <название>` — создать новый канал и сразу его выбрать

Как работает: как только бот отвечает «сообщите» на предложение, в канал уходит карточка договора
(партнёр, ссылка на пост, число тапов, чат, время). Когда тап выполнен — **та же карточка
редактируется** и получает статус ✅ с числом реально тапнувших каналов. Если тап сорвался — статус ❌ с причиной.
Пишет в канал аккаунт пользователя, поэтому он должен состоять в канале и иметь право писать.

## Команды владельца

- `/genkey` — выдать одноразовый ключ регистрации
- `/users` — список пользователей (вход, число чатов и каналов)
- `/revoke <id>` — удалить пользователя вместе с его данными

## Миграция со старой версии

Происходит автоматически при первом запуске:

- сессия, чаты, каналы, папки, автопост и лог-канал из старого `config.json` переезжают **владельцу** (`ownerId`);
- пользователи из старого `store.json` получают пустые карточки — им нужно залогиниться самим;
- общие поля из `config.json` удаляются, чтобы больше никто не наследовал чужие данные;
- в конфиг пишется флаг `migratedToMultiuser`, повторно миграция не запускается.

Если `ownerId` в старом конфиге не был задан, сессия не переносится — владелец просто делает `/login` заново.

## Запуск

```bash
npm install
# в config.json (или переменных окружения BOT_TOKEN / API_ID / API_HASH) укажите botToken, apiId, apiHash
node index.js
```

Данные хранятся в каталоге `CONFIG_DIR` (по умолчанию `/app/data`): `config.json` и `users.json`.
**Важно:** этот каталог должен быть на постоянном диске (volume), иначе при передеплое всё сбросится —
раньше `store.json` писался рядом с кодом и терялся при каждом обновлении.

## Попутные исправления

- `t.me/c/<id>/<msg>`: id чата собирался как `-100 + число` (арифметика вместо строки) — ссылки на приватные каналы не резолвились. Исправлено.
- Число тапов из предложения («вз 30») теперь реально ограничивает количество каналов; раньше значение считывалось, но игнорировалось.
- Убран отладочный вывод всего списка `send-as` на каждый тап.
- Личные настройки (`/settings`, `/set`): число тапов по умолчанию, ключевые слова, реакция на общие предложения — у каждого свои.
- `/logout`, `/api <apiId> <apiHash>` — на случай, если пользователь хочет свои api-ключи вместо общих.
